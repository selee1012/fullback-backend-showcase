## 1. 문제 정의 — 왜 이 서비스가 필요한가?

| # | 문제 | 근거 |
| --- | --- | --- |
| 01 | **방한 외국인 급증 vs 정보 접근성 부재** | 2026년 방한 관광객 2,000만 명 돌파 전망. 급증하는 수요 대비 외국인용 디지털 가이드는 여전히 부족 |
| 02 | **언어 장벽으로 인한 정보 비대칭** | 재한 외국인 최대 고충이 언어 문제(43.4%). 단순 번역 불편이 아니라 **실질적인 정보 접근 차단**으로 이어짐 |
| 03 | **트레킹 문화 급성장 속 외국인 소외** | 국민 77%가 등산·트레킹을 즐기지만, 한국인에게 일상인 산책 문화에 외국인은 다국어 정보 부재로 참여가 제한됨 |
| 04 | **공공데이터의 낮은 활용성** | 서울시 두드림길 데이터는 텍스트·행정 데이터 형태로만 제공. 비정형 경로 정보는 일반 지도 서비스만으로 전달 불가 |

**결론** → 외국인이 *산책로 + 주변 인프라*를 한 화면에서 볼 수 있는 서비스가 필요하다.

## 2. 솔루션 및 차별점

각 문제에 1:1로 대응하는 해결책을 설계했습니다.

### 01. 접속 즉시 쓰는 외국인 전용 가이드 — `Zero-Barrier`

- 외국인을 **1차 타겟**으로 한 전용 서비스
- 회원가입·로그인 없이 **위치 동의만으로 전 기능 즉시 이용**
- 기존 앱의 진입장벽(본인인증, 회원가입) 자체를 제거

> **백엔드 구현**: 최초 진입 시 `POST /api/guest`로 UUID를 발급하고, 이후 모든 쓰기 요청(좋아요·리뷰·쪽지)에서 이 UUID로 사용자를 식별. 인증 서버 없이 어뷰징 방지를 위한 이력 테이블(`CourseLikeHistory`, `ReviewLikeHistory`)로 중복 행위를 차단.

### 02. 한국어를 몰라도, 태그만으로 — `No-Search`

- 다국어 UI (영어 · 중국어 실시간 전환)
- 한국어 검색어 입력 자체가 부담이므로, `#숲길` `#야경` `#맛집` 등 **태그만으로 코스 필터링**

> **백엔드 구현**: 다국어를 별도 번역 API가 아닌 **컬럼 단위 이원화**(`name_eg`/`name_ch`, `tag_eg`/`tag_ch`, `description_eg`/`description_ch`)로 저장. `language=ENG|CHI` 파라미터로 응답 시점에 언어를 선택하므로 조회 경로에 외부 의존성이 없음.

### 03. 일상 트레킹을, 외국인도 한 화면에서

- 서울 두드림길 산책로를 다국어로 큐레이션
- 반경 내 맛집·관광지까지 **한 동선에 통합(올인원)**
- 외국인도 로컬 트레킹 문화에 참여

> **백엔드 구현**: `Course ↔ Place`를 `PlaceRecommend` 매개 엔티티로 N:M 연결. 코스 상세 진입 시 `GET /api/place?course_id={id}`로 큐레이션된 주변 인프라를 한 번에 조회.

### 04. 공공데이터를, 걸을 수 있는 지도 경로로

- **TM(EPSG:5181) → WGS84 좌표 변환** (Proj4)
- ETL로 텍스트·행정 형태의 두드림길 데이터를 지도 위 정밀 GIS 경로로 재구성

> **백엔드 구현**: 변환된 경로를 `LINESTRING SRID 4326`, 시작점을 `POINT SRID 4326`으로 저장하고 MySQL Spatial 인덱스를 적용. `ST_Distance_Sphere`로 반경 검색·거리 정렬을 DB에서 처리.

## 3. 핵심 기능 6종

| # | 기능 | 넣은 이유 |
| --- | --- | --- |
| 01 | **게스트 UUID 발급 + 다국어(영/중)** | 가입 장벽·언어 장벽 제거 (Zero-Barrier) |
| 02 | **산책로 목록·상세 / 거리 기반 탐색** | 외국인이 현재 위치 기준으로 코스를 바로 탐색 |
| 03 | **태그 필터** | 한국어 검색어 입력 부담 제거 (No-Search) |
| 04 | **주변 맛집·관광지 (반경 조회)** | 산책로와 주변 정보의 단절 해소 |
| 05 | **위치기반 쪽지 + 리뷰** | 단순 열람 → 사용자 참여형 커뮤니티 |
| 06 | **비속어 필터** | 다국어 커뮤니티 신뢰도 보호 |

### 01. 게스트 UUID 발급 + 다국어(영/중)

- 로그인 제거 → 진입 장벽 최소화, UUID 발급으로 사용자 식별
- 회원가입 없이 즉시 이용 가능
- 영어·중국어 제공으로 대부분의 외국인 사용자 커버

### 02. 산책로 목록·상세 / 거리 기반 탐색

- 사용자 GPS 기준 주변 산책로 조회 → 가까운 코스부터 한눈에 확인
- 난이도 · 거리 · 소요시간 등 정보 제공
- 주변 식당 · 랜드마크 정보까지 함께 확인

### 03. 태그 필터

- 외국인에게 동·구 기반 지역 검색은 활용도가 낮다고 판단
- 태그 기반 필터로 원하는 카테고리의 산책로 탐색
- 직관적인 카테고리 선택으로 접근성 향상

지원 태그 8종: `Landmark` `Night_View` `Forest_Trail` `Field` `River` `Spring_Flower` `Near_Subway` `Restaurant`
(중국어 대응: `地标` `夜景` `森林小道` `田野` `河边` `春花` `地铁附近` `美食`)

### 04. 주변 맛집·관광지 (반경 조회)

- 코스 정보에 그치지 않고 주변 정보까지 제공
- 코스 주변 맛집 · 관광지 추천 → 산책과 여행을 한 번에 연결

### 05. 위치기반 쪽지 + 리뷰

- 단순 정보 제공을 넘어 커뮤니티 시스템 구축
- 위치 기반 쪽지로 사용자 간 소통
- 리뷰를 통한 경험 공유 및 신뢰도 형성

### 06. 비속어 필터

- 건전한 커뮤니티 문화 형성을 위한 장치
- **LLM API 기반 비속어·욕설 필터링**
- **LLM 오류 시 Rule-Based 방식으로 자동 전환** (단어 리스트 매칭 차단)

→ 상세 설계는 [06. LLM 비속어 필터링](06-llm-moderation.md) 참고

## 4. 개발 과정의 의사결정 (Before → After)

발표에서 별도 슬라이드로 다룬, **외국인 경험을 해칠 수 있는 부분**을 찾아 개선한 4가지 사례입니다.

| # | BEFORE (한계) | AFTER (개선) |
| --- | --- | --- |
| 01 | 카카오맵의 다국어 한계 | **구글맵 전환** |
| 02 | UI에 한글 잔존 | **다국어 전수 점검** |
| 03 | 주변 관광지 데이터 부족 | **크롤링 및 데이터 보강** |
| 04 | 커뮤니티 신뢰도 문제 | **다국어 금칙어 필터 — LLM 적용** |
