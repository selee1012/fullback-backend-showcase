## 요약문

본 보고서는 재한 외국인 유학생 및 관광객이 겪는 정보 소외와 언어 장벽 문제를 해결하기 위한 **'서울시 공공데이터 기반 외국인 맞춤형 다국어 산책로 통합 플랫폼(GlobalStep)'** 의 개발 결과를 요약한다. 시스템은 Next.js 프론트엔드와 Spring Boot 3.x 백엔드 아키텍처로 구현되었으며, 표준 위경도 좌표 변환 엔진(Proj4) 및 MySQL Spatial Extension 공간 인덱싱을 활용하여 사용자의 실시간 GPS 반경에 따른 최적의 다국어 경로 및 주변 인프라 정보를 제공한다.

기존 글로벌 맵 서비스의 단편적인 경로 안내 체계와 언어적 미스매치로 인해 국내 거주 외국인의 과반수가 일상적인 보행 환경 구축에 어려움을 겪는 한계를 확인하고, **Pugh Method** 등의 아이디어 평가를 거쳐 **No-Search 태그 필터링**이 결합된 맞춤형 다국어 도보 가이드 플랫폼을 채택하였다. 핵심 KPI로는 다국어 추천 정보 만족도 5점 만점 기준 4.0점 이상을 설정하였다.

특히 본 플랫폼은 단순 경로 매핑을 넘어 코스 반경 100m 이내 사용자 검증 조건이 결합된 **'LBS 쪽지 커뮤니티(히트맵 오버레이)'** 와 **'구글·카카오맵 외부 딥링크 내비게이션 연동'** 을 구축하여 차별화된 사용성을 확보하였다. 최종 평가 결과, 사용자 수용성 테스트(UAT) 만족도 **4.2점**을 기록하여 목표치를 달성하였으며, k6 기반 부하 테스트를 통해 **동시 요청 가용성 100% 및 평균 응답 시간 16.9ms**를 검증하며 시스템의 우수한 안정성과 처리 효율성을 객관적으로 입증하였다.

## Abstract

This report summarizes the development of **"GlobalStep,"** an AI-assisted, multi-language pedestrian trail and restaurant integration platform designed for foreign students and tourists in Korea. The system is built on a decoupled 3-tier architecture featuring a Next.js frontend and a Spring Boot 3.x backend, utilizing the Proj4 coordinate conversion engine and MySQL Spatial Extension indexing to deliver real-time, location-based services (LBS).

Existing mapping applications often present fragmented pathing and language mismatch issues, creating significant informational barriers for foreign residents. Through structured idea evaluations like the Pugh Method, the team finalized a 'No-Search' tag-filtered multilingual trail platform, setting a target key performance indicator (KPI) of ≥ 4.0 out of 5.0 in user information satisfaction. GlobalStep extends basic routing by integrating a 100m proximity-verified 'LBS Note Community' with a heatmap overlay and seamless deep-linking to major external navigation tools (Google/Kakao Maps).

In the final evaluations, the platform achieved a User Acceptance Testing (UAT) score of **4.2**, satisfying the project requirements. Furthermore, k6 stress testing demonstrated a **100% success rate with an average system latency of 16.9ms**, validating the robust performance and ultra-low response speed under peak loads.

## I. 서론

최근 방한 외국인 관광객 및 유학생이 지속적으로 증가하며 한국의 트레킹 문화를 체험하고자 하는 수요가 확대되고 있으나, 국내 산책로 정보는 여전히 한국어 중심의 폐쇄적인 형태로 제공되고 있다. 기존 지도 및 공공 서비스는 복잡한 본인 인증 절차와 텍스트 검색 방식을 요구하여 외국인의 실질적인 정보 접근성을 제한한다는 한계가 있다.

본 프로젝트의 통계 조사에 따르면, **재한 외국인의 약 43.4%가 언어 장벽으로 인한 여가 생활의 불편함**을 겪고 있는 것으로 나타났다. 또한 서울시의 '두드림길' 등 기존 공공데이터는 우수한 코스 정보를 포함하고 있음에도 불구하고, 홍보가 제대로 되어 있지 않고 한국어로만 서비스되고 있어 외국인이 직관적으로 경로를 탐색하기 어려운 실정이다.

이러한 배경과 문제의식에 따라, 본 프로젝트는 복잡한 인증 절차가 없는 **'Zero-Barrier UX'** 를 지향하고, 비정형 경로 정보와 주변 인프라를 외국인 시각에 맞춰 재구성한 전용 다국어 통합 가이드 플랫폼을 개발하기 위해 추진되었다.

## II. 설계/프로젝트의 현실적 제한조건

### 1. 데이터 정합성 및 정밀도 확보
서울시 공공데이터의 평면좌표(TM)를 글로벌 지도 서비스와 연동하기 위해 위경도 좌표계(WGS84)로 변환해야 했으며, 구글 맵 레이어 위에서 정합성을 100% 달성하기 위한 정밀도 확보 과정이 필요하였다.

### 2. 리소스 안정성 및 데이터 휘발성 방지
공공데이터가 제공하는 외부 이미지 링크의 휘발성 문제를 해결하기 위해, 모든 외부 자산을 **AWS S3에 아카이빙**하고 Presigned URL 캐싱 전략을 도입하여 데이터의 영속성을 보장해야 했다.

### 3. 클라이언트 렌더링 성능 제약
다량의 연속된 트랙 좌표 데이터(Polyline) 렌더링 시 발생하는 브라우저 성능 저하를 방지하기 위해, 데이터 경량화 로직을 도입하고 **MySQL 공간 인덱싱**을 통해 데이터 서빙 환경을 최적화해야 했다.

### 4. 비용 효율성 및 예산 제약
상용 인프라 운영 예산의 한계로 인해 시스템 전체를 **AWS 프리티어 및 크레딧 한도 내**에서 운영해야 했으며, 추가 비용 억제를 위해 MySQL 등 검증된 오픈소스 기술 스택을 활용하여 경제성을 확보해야 했다.

### 5. 촉박한 개발 기간 및 마일스톤 제약
데이터 전처리부터 클라우드 최종 배포까지 전 과정을 **단 8주 이내**에 완료해야 했으므로, 일정 관리 하에 핵심 기능 중심의 최소 기능 제품(MVP)을 빠르게 완성하는 효율적인 프로세스가 요구되었다.

## III. 설계 목적

1. **No-Search 및 다국어(영·중 간/번체) UI** 제공을 통해 외국인 사용자의 정보 획득 시간(Time on Task) 1초 미만 달성
2. 회원가입이 없는 **Zero-Barrier 환경**에서 실시간 GPS 위치 및 추천수 기반 복합 가중치 알고리즘을 활용한 **반경 3km 내 맞춤형 산책로 추천** 기능 제공
3. 선택된 산책로 중심의 로컬 인프라 연동을 통해 외국인 선호도가 높은 **반경 내(기본 1km, 최대 5km) 맛집 및 관광지 추천** 환경 구축
4. 로그인 절차 없이 발생하는 중복 클릭 및 추천 어뷰징 행위를 **쿠키(Cookie) 기반 감지 로직**으로 효율적으로 억제하는 보안 체계 확립
5. 서울 전역 **100개 이상의 GIS 기반 정밀 트랙 데이터셋**과 **100개 이상의 정제된 주변 로컬 인프라 정보**를 관계형 데이터베이스(RDB)에 안정적으로 적재 및 관리
6. **MySQL 공간 인덱싱(Spatial Indexing) 최적화**를 통해 다량의 좌표 데이터 검색 및 동시 접속 환경에서의 1초 미만 초고속 응답 속도 확보

## IV. 설계 요약

### 1. 서비스 플로우 (10단계)

| 단계 | 내용 |
| --- | --- |
| ① 위치 권한 및 LBS 활성화 | 서비스 접속 시 실시간 GPS 기반 위치 정보 수집을 수락하고 '내 주변' 중심의 LBS 환경을 활성화 |
| ② 다국어 환경 선택 | 진입 화면에서 영어/중국어를 선택하면 전체 UI와 데이터 레이어가 실시간 전환 (기본값 영어) |
| ③ No-Search 태그 필터링 | 텍스트 타이핑 없이 아이콘 중심 카테고리 태그로 산책로 및 주변 인프라를 1차 탐색 |
| ④ 반경 기반 동적 경로 서빙 | 현재 위치 반경 3km 이내 산책로 존재 여부를 자동 연산. 없으면 지도 축척을 **전역으로 동적 확장(Zoom-out)** 하여 최적 코스 추천 |
| ⑤ 단락별 정보 레이어 제공 | 코스 선택 시 하단에 요약 '간이 페이지' 확장 → 추가 인터랙션으로 '상세 페이지' 라우팅 |
| ⑥ 히트맵 및 데이터 오버레이 | 상세 진입 시 사용자 밀집도 '코스 히트맵' 렌더링. 사이드 컨트롤로 스트릿뷰·맛집·랜드마크 레이어를 개별 오버레이 |
| ⑦ 위치 검증 기반 LBS 쪽지 | 코스 반경 100m 이내에 있음이 GPS로 검증된 경우에 한해 히트맵 위에 쪽지 생성 가능 |
| ⑧ 경험 피드백(리뷰) 시스템 | 이용 완료 사용자를 대상으로 평점 및 텍스트 리뷰 등록 피드백 루프 구동 |
| ⑨ 글로벌 모빌리티 딥링크 | 구글맵/카카오맵 원클릭 외부 내비게이션 연동 — 현재 위치에서 코스 진입점까지 도보 길찾기 동기화 |
| ⑩ 로컬 인프라 상세 서빙 | 주변 맛집·랜드마크를 그리드로 제공, 클릭 시 다국어 상세 팝업 및 구글맵 외부 라우팅 |

### 2. 기능 및 구성 요소

**프론트엔드 (Frontend)**
Next.js 및 React 기반 아키텍처를 바탕으로 회원가입이 없는 Zero-Barrier UX를 구현. 영어 및 중국어(간체/번체) 실시간 다국어 로컬라이제이션 체계를 갖추었으며, 사용자 여정에 따라 '간이 요약'과 '상세 분석' 레이어로 이원화된 인터페이스를 제공. 지도 API 상에 코스 히트맵 오버레이, 구글 스트릿뷰, 주변 인프라 요소를 선택적으로 시각화하는 동적 렌더링 환경 구축.

**백엔드 (Backend)**
Spring Boot 3.x 프레임워크 환경에서 비즈니스 로직의 트랜잭션 안정성을 보장. 다국어 매핑 데이터 서빙, 코스별 리뷰 관리 시스템을 처리하며, 특히 GPS 좌표 기반으로 사용자가 산책 코스 반경 100m 이내에 위치하는지 검증하여 조건 충족 시에만 위치 기반 쪽지(Note) 생성을 허용하는 **LBS 커뮤니티 통제 API**를 제공.

**공간 쿼리 및 데이터 엔진 (Data Engine)**
Proj4 라이브러리를 통해 서울시 공공데이터의 평면좌표(TM)를 위경도 좌표(WGS84)로 오차 없이 변환·적재. MySQL Spatial Extension의 공간 인덱싱을 활용하여, 사용자 위치 반경 3km 이내 경로 존재 여부를 탐색하고, 데이터 미존재 시 지도 축척을 전역으로 동적 확장(Zoom-out)하여 전체 코스를 재추천하는 예외 처리 및 공간 쿼리 최적화 알고리즘을 구동.

**외부 인프라 및 모빌리티 연동 (Integration)**
카카오맵 및 구글 맵 API의 외부 내비게이션 딥링크 연동 모듈을 구현하여, 사용자의 현재 위치에서 산책로 입구 진입점까지의 실시간 도보 길찾기 서비스를 지원. 또한 주변 맛집·랜드마크 장소명 클릭 시 구글맵 외부 상세 링크로 즉시 라우팅하는 크로스 플랫폼 맵핑 구조를 완성.

**보안 및 어뷰징 방지 (Security)**
별도의 회원 인증 절차가 없는 환경적 특성을 고려하여, 동일 코스에 대한 악의적인 중복 평점 등록 및 추천수 조작 행위를 차단하기 위해 **쿠키 및 클라이언트 IP 식별 기반의 다중 어뷰징 감지 필터**를 구현하여 데이터의 신뢰성을 확보.

### 3. 아키텍처

AWS 클라우드 인프라(Amazon EC2, RDS, S3)와 GitHub Actions CI/CD를 중심으로 구성되었으며, MySQL Spatial 공간 인덱싱 및 외부 내비게이션 딥링크 연동을 도입한 **3-Tier 구조**를 적용하였다.

## V. 설계 결정의 논의

### 1. 아이디어 및 아키텍처 선정 과정
브레인스토밍을 통해 도출된 여러 공간 정보 가이드 후보 중, **가중순위비교법과 Pugh Method** 평가를 거쳐 GlobalStep을 최종 선정하였다. 선정 기준은 ① 글로벌 타겟 사용자의 정보 소외 해결력, ② 오픈소스 기술을 통한 실행 가능성, ③ No-Search 기반의 사용자 요구 대응성이었다.

### 2. 백엔드 프레임워크 전환 및 설계 배경 (Spring Boot 3.x 도입)
초기 설계 단계에서는 가벼운 웹 서빙 구조를 고려하였으나, **다국어 맵핑 테이블 아키텍처의 트랜잭션 안정성**과 대용량 데이터 처리 효율을 확보하기 위해 백엔드를 Spring Boot 3.x 프레임워크 환경으로 전격 전환하였다. 이를 통해 복잡한 LBS 비즈니스 로직과 데이터 정합성을 안정적으로 제어할 수 있는 구조를 확립하였다.

### 3. 공간 쿼리 최적화 및 렌더링 성능 개선
대량의 연속된 트랙 좌표 데이터(Polyline) 렌더링 시 발생하는 클라이언트 측 병목을 해결하기 위해 프론트엔드 데이터 경량화 로직을 도입하였다. 또한 MySQL Spatial Extension의 공간 인덱싱을 적용하여 **사용자 위치 반경 3km 내 경로 검색 및 랭킹 연산 시간을 1초 미만**으로 단축하며 시스템 성능을 최적화하였다.

### 4. 피드백 기반의 기능 고도화 및 사용자 리뷰 반영
개발 중기 및 사용자 리뷰 단계에서 도출된 외국인 사용자의 실제 니즈를 바탕으로 핵심 기능을 대폭 확장하였다. 텍스트 검색 한계를 극복한 'No-Search 태그 및 간이/상세 이원화 레이어 UI'를 도입하였으며, 코스 반경 100m 이내 위치 검증 조건이 결합된 'LBS 쪽지 커뮤니티(히트맵 오버레이)' 및 '구글·카카오맵 외부 딥링크 내비게이션 연동' 기능을 추가하여 서비스의 실용성과 가독성을 획기적으로 개선하였다.

## VI. 설계 평가

### 1. 시험 계획
재한 외국인 유학생 및 관광객 **5~10명**을 대상으로 사용자 수용성 테스트(UAT) 및 만족도 설문조사를 진행하고, 실제 산책로 현장 방문을 통한 **GPS 트래킹 대조 테스트**를 수행하였다. 또한 시스템의 한계 성능을 검증하기 위해 **k6 기반의 가상 사용자(VU) 부하 시뮬레이션**을 가동하여 대량 동시 접속 환경에서의 백엔드 응답성 및 안정성 평가를 병행하였다.

### 2. 평가지표

| 지표 | 목표 |
| --- | --- |
| Top-3 코스 추천 및 다국어 정보 만족도 | 5점 만점 기준 4.0점 이상 |
| 부하 환경에서의 시스템 가용성 및 성능 | 가용성 99% 이상, 평균 지연 시간 1초 미만 |
| UI/UX 편의성 및 과업 완수 효율성 | Zero-Barrier 및 No-Search 만족도 |
| GIS 경로 정합성 및 위치 정밀도 | 원천 좌표 변환에 따른 위치 오차 10m 이내 |

### 3. 결과

- **UAT**: 코스 추천 및 다국어 정보 제공 만족도 5점 만점 중 **4.2점**으로 목표치(4.0점) 상회. 특히 회원가입 없이 즉각적인 다국어(영·중) 매핑 화면을 제공하고, No-Search 태그로 쉽게 진입할 수 있는 구조에 대해 높은 편의성 점수를 획득.
- **부하 테스트**: 총 **2,166회의 데이터 요청** 처리 중 단 1건의 에러도 발생하지 않아 HTTP 성공률 **100%** 달성. 대량의 좌표 데이터(Polyline) 및 공간 쿼리 연산이 수반됨에도 **평균 응답 시간 16.9ms**, 최대 부하 시에도 **218ms 이내**로 제어되어 목표치(1초 미만)를 압도적으로 초과 달성.
- **현장 GPS 대조 시험**: 1차 테스트에서 발견된 일부 좌표 꼬임 문제를 MySQL 공간 인덱싱 적용 및 데이터 경량화로 보완, **오차 범위 10m 이내**의 정밀한 경로 정합성을 전수 확인.

### 4. 분석

데이터 엔진 최적화와 No-Search 태그 인터페이스 도입이 실제 타겟 사용자인 외국인의 정보 접근성을 향상시키고 높은 만족도(4.2점)를 견인했음이 정량적으로 증명되었다. 특히 부하 테스트 상에서 나타난 **16.9ms의 평균 응답 시간**은 MySQL Spatial Indexing과 Spring Boot 3.x 기반 아키텍처가 동시 대량 요청 환경에서도 병목 없이 안정적으로 가동되고 있음을 객관적으로 입증한다.

다만, 비인증 LBS 커뮤니티 특성상 발생할 수 있는 악성 유저의 리뷰/쪽지 도배 어뷰징 우려와 초기 데이터셋의 행정 구역별 편중 현상은 한계로 남았으며, 이는 향후 다국어 금칙어 자동 필터링 시스템 도입 및 전국 단위 데이터 확충을 통해 지속적으로 보완할 계획이다.

## VII. 결론

본 프로젝트는 재한 외국인 관광객 및 유학생이 겪는 정보 소외와 언어 장벽 문제를 서울시 공공데이터 재가공과 사용자 중심 설계를 통해 해결하는 데 기여하였다. 핵심 설계 목표였던 **다국어 정보 만족도(5점 만점 중 4.2점)** 달성과 k6 부하 테스트를 통한 대규모 동시 접속 환경에서의 **안정성(평균 응답 시간 16.9ms, 성공률 100%)** 을 성공적으로 검증하였다.

다만, 회원가입이 없는 비인증 환경 특성상 발생할 수 있는 중복 리뷰/쪽지 도배 등의 어뷰징 제어 문제와 특정 행정 구역에 국한된 산책로 데이터 편중 현상은 향후 과제로 남아 있다.

추후에는 **실시간 다국어 금칙어 자동 필터링 시스템 도입**을 통한 커뮤니티 신뢰도 확보, **서울 외 전국 단위로의 공공데이터 확장**, 그리고 사용자의 성향을 고려한 **협업 필터링 알고리즘 결합** 등 기능 고도화를 통해 글로벌 종합 관광 플랫폼으로서의 지속적인 발전이 가능할 것으로 판단된다.
